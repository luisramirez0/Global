## Corrección del contrato de C-08
El handoff de C-08 (§"Contrato para C-15") dice que `GET /api/auditoria?entidadId=<pacienteId>` "devuelve todos los accesos a la historia clínica del paciente". **No es exacto**:
- `entidadId` compara solo el número y no depende de la entidad. `?entidadId=5` también trae filas de `Turno` con `entidadId = 5` (el turno 5) y de `Usuario` (`LOGIN` del usuario 5). Lo caracteriza `PacienteExportAuditoriaIT.entidadIdAloneMatchesEveryEntityWithThatNumber`.
- Los accesos a turnos se auditan con el id del turno (C-07). No se pueden vincular al paciente por este filtro.
- **Uso correcto**: combinar siempre `entidad` con `entidadId`, una entidad por pedido:
  - `?entidad=FichaClinica&entidadId=<pacienteId>`
  - `?entidad=NotaClinica&entidadId=<pacienteId>`
  - `?entidad=ConsentimientoDatos&entidadId=<pacienteId>`
  - `?entidad=Paciente&accion=EXPORT&entidadId=<pacienteId>`
- La UI de `#/auditoria` lo aplica: el campo de número de entidad solo se habilita con una entidad elegida. El cliente lanza un error de programación si recibe `entidadId` sin `entidad`.
- Queda documentado en la spec `audit-log` (escenario "Id de entidad compartido entre entidades").
- Una vista "historial clínico del paciente" en un solo pedido (filtro multientidad) queda como mejora post-entrega; requiere tocar `auditoria/consulta` (C-06, zona de riesgo).

## Contrato del export (para C-12, C-16 y consumidores)
- `GET /api/pacientes/{id}/export`:
  - `ADMIN`/`PROFESIONAL` → `200`.
  - `RECEPCION` → `403`; sin token → `401`.
  - Paciente inexistente o de otro consultorio → `404`.
  - Fallo de auditoría → `500` genérico.
  - Ningún rechazo deja fila `EXPORT`.
- Cuerpo:
  ```json
  {
    "exportadoEn": "<Instant UTC>",
    "paciente": { "id", "nombre", "apellido", "dni", "fechaNacimiento", "sexo", "telefono", "email", "direccion", "obraSocialTexto", "activo" },
    "consentimientos": [ { "id", "versionTexto", "aceptadoEn", "registradoPorUsuarioId" } ],
    "ficha": { "alergias", "medicacionActual", "antecedentesMedicos", "enfermedadesRelevantes", "embarazo", "motivoConsulta", "observaciones", "actualizadaEn" } | null,
    "notas": [ { "id", "fecha", "profesionalId", "turnoId", "texto" } ],
    "turnos": [ { "id", "inicio", "fin", "estado", "sobreturno", "motivoCancelacion", "notas", "profesionalId", "prestacion": { "id", "nombre" }, "sillon": { "id", "nombre" } } ]
  }
  ```
- Orden: consentimientos del más reciente al más antiguo; notas y turnos cronológicos ascendentes. Sin paginar.
- No incluye consultorio, `version`, `createdAt`/`updatedAt` ni el log de auditoría.
- Paciente dado de baja o sin consentimiento: se exporta (`activo: false`; `ficha: null` y listas vacías si corresponde).
- Auditoría: `EXPORT` · `Paciente` · `entidadId = pacienteId` · detalle `{"consentimientos":n,"ficha":bool,"notas":n,"turnos":n}`.
